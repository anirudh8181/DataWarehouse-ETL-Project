# ETL - Detailed Notes

Notes reconstructed from `ETL.drawio`. The diagram is a mind map with **ETL** at the center, branching into three color-coded pillars:

- **E - Extraction** (green)
- **T - Transformation** (red)
- **L - Load** (blue)

ETL is the process of moving data from source systems into a target system (data warehouse / lake) by **Extracting** it, **Transforming** it into a usable shape, and **Loading** it into the destination.

---

## 1. Extraction (E)

Pulling raw data out of source systems. The diagram splits Extraction into three sub-areas: **Methods**, **Types**, and **Techniques**.

### 1.1 Extraction Methods
How the data movement is initiated.

| Method | Description |
|---|---|
| **Pull Extraction** | The ETL/target system reaches out and requests (pulls) data from the source on its own schedule. |
| **Push Extraction** | The source system sends (pushes) data to the ETL pipeline, often event-driven or on the source's schedule. |

### 1.2 Extraction Types
How much data is pulled each run.

| Type | Description |
|---|---|
| **Full Extraction** | The entire dataset is extracted every time. Simple but expensive; no need to track changes. |
| **Incremental Extraction** | Only new or changed records since the last run are extracted. Efficient; requires a way to detect changes (timestamps, IDs, CDC). |

### 1.3 Extraction Techniques
The concrete mechanisms used to get the data.

- **Manual Data Extraction** - manually exporting/copying data.
- **Database Querying** - running SQL queries against source databases.
- **File Parsing** - reading structured/semi-structured files (CSV, JSON, XML, etc.).
- **API Calls** - fetching data from REST/other APIs.
- **Web Scraping** - extracting data from web pages.
- **Event Based Streaming** - consuming continuous event streams (e.g. Kafka).
- **CDC (Change Data Capture)** - capturing row-level changes from database logs for near-real-time incremental extraction.

---

## 2. Transformation (T)

Converting raw extracted data into clean, consistent, business-ready form. The diagram lists these transformation categories:

### 2.1 Data Integration
Combining data from multiple sources into a unified view.

### 2.2 Data Enrichment
Enhancing data by adding related/derived information from other sources.

### 2.3 Data Cleansing
Fixing quality issues in the data. This is the largest sub-branch:

- **Handling Missing Data** - impute, default, or drop null/absent values.
- **Remove Duplicates** - de-duplicate repeated records.
- **Handling Invalid Values** - correct or reject values that break rules/constraints.
- **Data Type Casting** - convert fields to correct data types.
- **Outlier Detection** - identify and handle anomalous values.
- **Data Filtering** - keep only relevant rows/columns.
- **Handling Unwanted Spaces** - trim leading/trailing/extra whitespace.

### 2.4 Data Aggregations
Summarizing data (sums, counts, averages, group-bys, rollups).

### 2.5 Derived Columns
Creating new columns computed from existing ones.

### 2.6 Data Normalization & Standardization
Bringing data to consistent formats, units, scales, and representations.

### 2.7 Business Rules & Logic
Applying organization-specific rules and calculations.

## 3. Load (L)

Writing transformed data into the target system. The diagram splits Load into **Processing Types**, **Slowly Changing Dimensions (SCD)**, and **Load Methods**.

### 3.1 Processing Types
How data is processed on the way in.

| Type | Description |
|---|---|
| **Batch Processing** | Data loaded in scheduled batches/chunks. |
| **Stream Processing** | Data loaded continuously in near-real-time as it arrives. |

### 3.2 Slowly Changing Dimensions (SCD)
Strategies for handling changes to dimension records over time.

| SCD Type | Behavior |
|---|---|
| **SCD 0 - No Historization** | Attributes are fixed; never change after initial load. |
| **SCD 1 - Overwrite** | New value overwrites the old; no history kept. |
| **SCD 2 - Historization** | Old record is preserved and a new versioned record is added; full history maintained. |
| **SCD ...** | Other variants (e.g., SCD 3 partial history, hybrids). |

### 3.3 Load Methods
How records are written, tied to Full vs Incremental loading.

**Full Load** (replace everything):
- **Truncate & Insert** - empty the target table, then insert all data.
- **Upsert** - insert new, update existing based on keys.
- **Drop, Create, Insert** - drop the table, recreate it, then insert.

**Incremental Load** (apply only changes):
- **Upsert** - insert new / update existing matched rows.
- **Append** - add new rows only.
- **Merge** - combine insert/update (and optionally delete) in one operation based on match conditions.
